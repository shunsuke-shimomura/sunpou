# ADR-002: ブロック行列の実装戦略

## 判断内容

固定サイズのジェネリック構造体 (`BlockMat2x2<A,B,C,D>`, `BlockMat3x3<...>`) と
trait bound による制約で実装する。

## 背景

状態遷移行列やEKF共分散行列はブロックごとに異なる物理次元を持つ。
これを型安全に扱う方法が必要。

## 選択肢

### A. 固定サイズジェネリック構造体 (採用)

```rust
pub struct BlockMat2x2<A, B, C, D> { ... }
impl Mul<BlockVec2<U, L>> for BlockMat2x2<A, B, C, D> where ... { }
```

- **Pros**: シンプルで理解しやすい。trait bound で制約が明示的。コンパイラが
  最適化しやすい。ユーザーが自由に新しいブロックサイズを定義できる。
- **Cons**: 2x2, 3x3 等をそれぞれ定義する必要がある。

### B. 型レベルリスト (HList)

```rust
type Stm = BlockMat<HList![UnitMat<...>, UnitMat<...>], HList![...]>;
```

- **Pros**: 任意のN×Mに汎用的。
- **Cons**: 型が非常に複雑になる。エラーメッセージが壊滅的。
  実装コストが高い。

### C. マクロによる構造体生成のみ

```rust
block_matrix! { OrbitalStm: [[rr, rv], [vr, vv]] }
```

- **Pros**: ボイラープレートが少ない。
- **Cons**: ジェネリクスで書けない。各具体型ごとにマクロ展開が必要。

## 結論

Aを採用。2x2と3x3を標準提供し、それ以上が必要な場合はユーザーが同じパターンで
定義できる。マクロは将来的にボイラープレート削減のために追加してもよいが、
ジェネリクスの制約が第一義。
