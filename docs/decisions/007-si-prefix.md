# ADR-007: SI プレフィクス (nano, kilo, mega 等) の型レベルサポート

## 判断内容

`Scalar<D, P = Z0>` に型パラメータ `P` (10の累乗) を追加し、
SI プレフィクスをコンパイル時に追跡する。デフォルトは `Z0` (プレフィクスなし)
で後方互換。

## 背景

nanoオーダーとmegaオーダーの数値を混在して計算すると、f64 の有効桁数
(約15-16桁) の範囲で精度低下が生じうる。特に加算時に大きな値と小さな値の
差が失われる (catastrophic cancellation)。

値を自然なスケールで保持し、スケールを型で追跡することで:
1. 内部値が1.0に近い範囲に保たれ、精度が向上する
2. 異なるスケールの加算は型エラーとなり、明示的な `rescale()` を要求する
3. 乗除算はスケールが自動的に加減算される (ゼロコスト)

## 設計

```rust
pub struct Scalar<D, P = Z0> {
    value: f64,           // value × 10^P × [SI base unit]
    _marker: PhantomData<(D, P)>,
}
```

### 演算規則

| 操作 | 入力 | 出力 |
|------|------|------|
| 加算 | `Scalar<D, P> + Scalar<D, P>` | `Scalar<D, P>` (同プレフィクスのみ) |
| 乗算 | `Scalar<D1, P1> * Scalar<D2, P2>` | `Scalar<D1×D2, P1+P2>` |
| 除算 | `Scalar<D1, P1> / Scalar<D2, P2>` | `Scalar<D1/D2, P1-P2>` |
| f64倍 | `Scalar<D, P> * f64` | `Scalar<D, P>` |
| 変換 | `s.rescale::<P2>()` | `Scalar<D, P2>` (値を 10^(P-P2) 倍) |
| 抽出 | `s.to_base_value()` | `f64` (値 × 10^P) |

### スコープ

Scalar のみにプレフィクスを追加。UnitVec / FrameVec / ElemMat / FrameElemMat は
プレフィクスなし (= 常に内部単位) で据え置く。

理由: ベクトル・行列の全要素が同じプレフィクスを共有するケースは稀。
スカラー演算の精度がプレフィクスの主要なユースケースであり、
ベクトルが必要な場合は `rescale()` で Scalar に変換してから操作する。

## 選択肢

### A. Scalar のみにプレフィクス (採用)

- **Pros**: 後方互換。変更量が少ない。主要ユースケースをカバー。
- **Cons**: ベクトル・行列にはプレフィクスなし。

### B. 全型にプレフィクス追加

- **Pros**: 完全なスケール追跡。
- **Cons**: const generics と type parameter の相互作用で Rust の制約に当たる。
  全 impl を書き換える必要がある。API が複雑化。

### C. ランタイムスケール

- **Pros**: 柔軟。
- **Cons**: ゼロコストでない。コンパイル時チェック不可。

## 結論

A を採用。将来必要になればベクトル・行列に拡張可能。
